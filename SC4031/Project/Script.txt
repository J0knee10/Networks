"Hello everyone. Today I am presenting my Hybrid Edge-Cloud Fall Detection System. To solve the challenge of high accuracy without draining IoT battery life, I implemented a two-stage cascade. **[0:45-1:45] Stage 1: Edge Detection & IMU Performance**
"The Android app monitors the 6-axis IMU at 120Hz. To avoid constant processing, the system uses a threshold trigger of 40 m/s². I trained a custom TensorFlow Lite CNN model specifically for this hardware. In my final evaluations, as shown in my report, this local model achieved an **accuracy of 83.33% with an F1-score of 0.84**. This provides a reliable 'first filter' to detect sudden impacts while running natively on the device. **(NEXT)**"

**[1:45-2:45] Stage 2: Cloud Verification & Audio Results**
"When Stage 1 triggers, the app streams 1-second audio chunks to a Flask server. To ensure we never miss a keyword, the server uses a 'Stateful Rolling Buffer'—it combines these chunks into a 2-second window and applies a sliding window search. The cloud model uses MFCC features and `SeparableConv2D` layers. During testing, this model was exceptionally robust, achieving **100% accuracy and precision** in identifying the 'HELP' and 'CANCEL' keywords. **(NEXT)**"

**[2:45-3:45] Advanced Features: Multi-User & Online Updates**
"For the advanced requirements, the system supports multiple concurrent users. The server uses a unique `deviceId` for each connection to maintain separate audio buffers. I also implemented **Online Model Updating**. If the system makes a mistake, the user can submit a correction. The app sends the audio and the correct label to the server's `/update` endpoint, which triggers `model.train_on_batch` to retrain the model in real-time. This allows the system to learn and improve while it's still running. **(NEXT)**"
